# ClipboardX 需求文档

## 1. 项目背景

Mac 用户在日常开发、办公、写文档、复制代码、复制链接时，经常会遇到复制内容被新内容覆盖的问题。ClipboardX 的目标是提供一个轻量、隐私优先、可搜索、可扩展同步的 macOS 剪贴板历史工具。

## 2. 产品目标

ClipboardX 第一阶段目标是实现一个可长期运行在 macOS 菜单栏中的剪贴板历史工具。

核心目标：

1. 自动记录用户复制过的内容。
2. 支持快速搜索历史内容。
3. 支持点击历史记录后重新写入系统剪贴板。
4. 默认本地存储，不上传云端。
5. 对敏感内容进行过滤，降低隐私风险。
6. 为后续多设备同步、快捷键粘贴、图片/文件支持预留架构。

## 3. 产品定位

> 一个轻量、隐私优先的 macOS 剪贴板历史与共享工具。

一句话描述：

> 复制过的内容不再丢失，文本、链接、图片、文件都能快速找回，并可在多台 Mac 间安全同步。

## 4. 用户场景

### 4.1 开发场景

用户复制过接口地址、Token 片段、SQL、日志、代码片段，希望稍后快速找回。

### 4.2 办公场景

用户在多个文档之间复制内容，希望快速复用之前复制过的文本、链接、文件路径。

### 4.3 写作场景

用户复制多个资料片段，希望在写作过程中快速调取历史内容。

### 4.4 多设备场景

用户有多台 Mac，希望历史内容可以通过 iCloud 或局域网同步。

## 7. 功能设计

### 7.1 剪贴板监听

使用 `NSPasteboard.general.changeCount` 判断系统剪贴板是否发生变化。

监听策略：

- 每 0.5 秒轮询一次。
- changeCount 变化后读取剪贴板内容。
- 当前支持读取文本、URL、文件 URL、图片数据。
- 内容为空时不保存。
- 命中敏感过滤规则时不保存。
- 命中重复内容时只更新时间，不重复插入。
- App 自身将历史记录写回剪贴板后，会标记当前 changeCount 为已处理，避免自写入内容被重复记录。

### 7.2 历史记录

历史记录字段：

| 字段 | 说明 |
|---|---|
| id | 唯一 ID |
| type | 内容类型，text/url/image/file/html/richText |
| content | 原始内容或资源路径；图片类型保存为本地 PNG 文件路径 |
| preview | 预览文本 |
| hash | 内容哈希，用于去重；图片类型基于 PNG 数据哈希 |
| sourceApp | 来源应用 |
| isPinned | 是否置顶 |
| createdAt | 创建时间 |
| updatedAt | 更新时间 |

### 7.3 搜索

搜索策略：

- MVP 采用内存过滤。
- 当前存储层已迁移到 SQLite，搜索仍采用内存过滤。
- 后续可改为 SQLite FTS5 查询。
- 搜索字段包括 content、preview、type、类型显示名、sourceApp。
- 当前支持按类型过滤：全部、文本、链接、文件、图片。

### 7.4 点击复制

用户点击某条历史记录后：

1. 清空系统剪贴板。
2. 将历史内容写入 `NSPasteboard.general`。
3. 更新该记录的 `updatedAt`。

不同类型写回策略：

| 类型 | 写回策略 |
|---|---|
| text | 写回 `.string` |
| url | 写回 `.string` |
| file | 写回文件 URL 对象 |
| image | 写回 PNG 图片数据 |

如果用户开启自动粘贴：

1. 写回剪贴板成功后隐藏历史窗口。
2. 激活打开历史窗口前的前台应用。
3. 在 Accessibility 权限已授权时模拟 `Cmd + V`。
4. 未授权时弹出系统辅助功能权限提示，不执行自动粘贴。

### 7.5 隐私过滤

默认过滤以下内容：

- `password=`
- `Authorization:`
- `Bearer `
- `sk-`
- `AKIA`
- `-----BEGIN PRIVATE KEY-----`
- `验证码`
- `verification code`

当前已支持：

- 默认敏感规则。
- 用户自定义敏感规则，保存在 `UserDefaults`。
- 忽略来源应用列表，命中 `sourceApp` 时不保存该条记录。
- 设置窗口中新增、删除、重置自定义规则。

### 7.6 图片资源管理

- 图片剪贴板内容会转成 PNG 后保存到 `~/Library/Application Support/ClipboardX/Images/`。
- SQLite 只保存图片路径和图片数据哈希，不直接保存大块图片二进制。
- 删除图片记录、清空历史、历史数量超限裁剪时，会同步清理无引用图片资源。

### 7.7 SQLite 持久化

- 历史数据保存到 `~/Library/Application Support/ClipboardX/clipboard-history.sqlite`。
- `clipboard_items` 表保存历史记录、内容类型、预览、哈希、来源应用、置顶状态和时间戳。
- `metadata` 表保存迁移标记等内部状态。
- 启动时加载 SQLite 数据到内存，列表展示和当前搜索仍优先使用内存缓存。
- 发现旧的 `clipboard-history.json` 且尚未迁移时，会自动解码并导入 SQLite。
- SQLite 启用 WAL journal，降低频繁写入对主数据库文件的影响。

### 7.8 截图贴片

- 菜单栏提供“截图并固定”入口。
- Option + Shift + A 可触发“截图并固定”。
- 第一版只支持区域截图。
- 截图完成后写入系统剪贴板。
- 截图保存为图片历史记录。
- 截图完成后打开浮动图片贴片。
- 支持同时存在多张贴片，用于并排对比。
- 贴片支持拖动、调整大小、关闭、重新复制到剪贴板。
- 贴片支持置顶/取消置顶层级切换。
- 关闭贴片不删除历史记录。
- 退出 App 后不恢复上次贴片布局。

### 7.9 局域网共享

- 局域网共享默认关闭，需要用户手动开启。
- 支持设置本机设备名。
- 通过 Bonjour 发现同一局域网内其他 ClipboardX 设备。
- 支持设备信任和配对请求。
- 未信任设备不能直接发送剪贴板内容。
- 支持从历史记录手动发送文本、链接和图片到指定已信任设备。
- 文件类型第一版不做真实文件传输。
- 接收端收到内容后进入待接收队列并提醒用户确认。
- 用户确认接收后保存到本机 ClipboardX 历史记录。
- 确认接收后默认不覆盖系统剪贴板，可在“局域网共享...”窗口中开启自动复制。
- 发送前继续使用敏感内容过滤规则。
- 菜单栏提供独立“局域网共享...”窗口，不放在设置页中，并展示待接收内容。
- 开发阶段可通过单机多实例/多端口思路模拟核心协议。
- 最终验收需要两台 Mac 真机验证发现、配对、发送和接收。

## 8. 非功能需求

### 8.1 性能

- 剪贴板监听不应明显影响系统性能。
- 历史记录列表打开响应时间应低于 300ms。
- 第一版建议最多保留 1000 条历史。
- 图片文件不直接写入 SQLite，避免数据库膨胀。

### 8.2 隐私

- 默认只本地保存。
- 默认不上传云端。
- 提供清空历史能力。
- 提供暂停监听能力。
- 图片资源保存在本机应用支持目录，不上传云端。
- 提供来源应用黑名单。
- 提供自定义敏感过滤规则。

### 8.3 可靠性

- App 异常退出不应影响系统剪贴板。
- 写入剪贴板失败时不应崩溃。
- 监听器应支持启动与停止。
- App 自身写回剪贴板后不应重复记录同一内容。
